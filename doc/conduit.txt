1. INTRODUCTION                                         *conduit-introduction*

conduit.nvim makes Neovim an Agent Client Protocol (ACP) client. It spawns an
ACP agent (Claude Code, Gemini CLI, Codex, ...) as a subprocess and talks
JSON-RPC to it over stdio. Agent file reads and writes go through loaded
buffers when there are any, so agents see unsaved changes.

See https://agentclientprotocol.com for the protocol.

==============================================================================
2. SETUP                                                       *conduit-setup*

>lua
  require("conduit").setup({
    default_agent = "claude",
    agents = {
      claude = { cmd = "npx", args = { "-y", "@agentclientprotocol/claude-agent-acp" } },
      gemini = { cmd = "gemini", args = { "--experimental-acp" } },
      codex = { cmd = "npx", args = { "-y", "@agentclientprotocol/codex-acp" } },
    },
    ui = {
      width = 0.4,
      input_height = 6,
      icons = false,
      spinner = { "⠋", "⠙", "⠹", "⠸", "⠼", "⠴", "⠦", "⠧", "⠇", "⠏" },
      inline = { width = { min = 40, max = 84 } },
    },
    inline = { agent = nil, options = {} },
    mentions = { completion = "auto" },
    threads = { scope = "cwd", persist = true, max_listed = 200, hide_inline = true },
    log_level = vim.log.levels.WARN,
  })
<
Each agent takes `cmd`, plus optional `args`, `env` and `options`. Calling
setup() is optional if you're happy with the defaults.

`ui.icons` adds Nerd Font glyphs to float titles. `ui.spinner` is the progress
animation; a single frame turns it off. `ui.inline.width` bounds the inline
prompt and answer floats. Floats use 'winborder' when it has a top edge, else
a rounded border.

                                                            *conduit-options*
`options` are session options applied to every new session, keyed by option id
or ACP category, e.g. `{ model = "opus", effort = "high" }`. `effort` is an
alias for the `thought_level` category. `inline.options` are layered over
them for inline edits. Values depend on the agent; see |:Conduit| `option`.

`threads` configures |conduit-threads|: `scope` is "cwd" (past threads started
in the current directory) or "all"; `persist` keeps a local index of thread ids
and titles (never transcripts); `max_listed` caps how many past threads are
fetched; `hide_inline` leaves inline requests' sessions out of thread lists.

3. COMMANDS                                                 *conduit-commands*

                                                                    *:Conduit*
:Conduit [toggle]       Toggle the chat window.
:Conduit open [agent]   Open the current thread. Naming a different agent
                        switches to its latest thread, or starts one.
:Conduit new [agent]    Start a new thread (chat and ACP session). Earlier
                        threads stay alive. See |conduit-threads|.
:Conduit threads [agent]
                        Pick a live or past thread, or start a new one.
:Conduit continue [agent]
                        Go back to the latest live thread, or reopen the
                        most recent past thread in this directory.
:Conduit thread {action} [title]
                        `new`, `next`, `prev`; `close` the current thread
                        (it stays in the history); `delete` it for good
                        (asks first); `fork` it; `rename` it.
:[range]Conduit add     Add [range] to the prompt as a fenced code block.
:[range]Conduit inline [request]
                        Edit [range] in place or answer a question about it
                        in a float, as the agent decides. Prompts for the
                        request when omitted. See |conduit-inline|.
:[range]Conduit ask [question]
                        Like `inline`, always answering in a float.
:[range]Conduit edit [instruction]
                        Like `inline`, always rewriting [range].
:Conduit model [value]  Pick or set the session model.
:Conduit effort [value] Pick or set the reasoning effort.
:Conduit mode [value]   Pick or set the session mode.
:Conduit option [id] [value]
                        Pick or set any session option.
:Conduit commands [name]
                        Pick one of the agent's slash commands (or use
                        [name]) and start the chat prompt with it. See
                        |conduit-slash-commands|.
:Conduit cancel         Cancel running inline edits, or else the chat turn.
:Conduit stop           Terminate all agent processes.
:Conduit log            Open the log file.

4. CHAT BUFFER                                                  *conduit-chat*

The chat is a markdown transcript with a prompt buffer below it.

  <CR>      (prompt, normal)  Send the prompt
  <C-s>     (prompt, insert)  Send the prompt
  <C-c>     (prompt, normal)  Cancel the running turn
  go        (both)            Pick a session option (model, effort, mode)
  gs        (both)            Pick a thread
  gn        (both)            Start a new thread with the same agent
  ]t  [t    (both)            Next / previous thread
  q         (both)            Close the chat window

Tool permission requests are shown with |vim.ui.select()|. The buffers use the
`conduit` and `conduit_input` filetypes with treesitter markdown highlighting,
so markdown linters and LSPs don't attach to them.

                                                            *conduit-threads*
Each chat is a thread: one ACP session with its own transcript. Starting a new
thread keeps the others alive, and switching shows the chosen thread in the
same chat windows. The winbar shows the thread's title and its position, e.g.
`(2/3)`. Titles come from the agent's `session_info_update`, from
`:Conduit thread rename` (these stick), or from the first line of your first
prompt. Inline answers moved into the chat (|conduit-inline|) become threads.

Beyond live threads, features follow the agent's capabilities:

  none                 Live threads until Neovim exits.
  loadSession          Reopen past threads, replaying their transcript. Past
                       threads come from conduit's local index.
  session list         Past threads come from the agent (`session/list`),
                       including ones started outside Neovim.
  session resume       Reconnect after the agent restarts without a replay.
  session close        Closing a thread frees the agent's session.
  session delete       Deleting removes it from the agent's history. Without
                       it, deleted threads are hidden from conduit's lists.
  session fork         `:Conduit thread fork`.
  session title        Renames are stored by the agent (`session/set_title`).

The picker (`gs`, |:Conduit| `threads`) lists live threads, then the agent's
past threads, then "New thread". When the agent process exits, the transcript
stays; the next prompt restores the session by resuming it, else reloading it
silently, else starting a new session with a notice. |:checkhealth| conduit
shows what each running agent supports. The local index is
`stdpath("data")/conduit/threads.json`.

                                                           *conduit-mentions*
Type `@` in the chat prompt or the inline prompt to attach context:

  @path/file      The file's contents (from its buffer if open)
  @dir/           A listing of the directory
  @buffer         The buffer you were last in
  @selection      Your last visual selection in that buffer
  @diagnostics    Diagnostics from all open buffers
  @quickfix       The quickfix list
  @diff           Uncommitted changes (`git diff HEAD`)

Mentions that don't match anything are left as plain text. Agents without
embedded-context support get resource links for files.

Completion uses blink.cmp when it is loaded (a `conduit` source is registered
for the `conduit_input` filetype automatically), otherwise the native popup.
Set `mentions = { completion = "blink" | "native" }` to force one.

                                                     *conduit-slash-commands*
Agents advertise their own commands (`available_commands_update`), such as
`/review`, `/compact` and `/init` for Claude Code. Type `/` at the very start
of the chat prompt or the inline prompt to complete them, with descriptions in
the completion docs. Commands that take arguments show their input hint as
ghost text after `/name ` until you type some. `:Conduit commands` lists them
with |vim.ui.select()|, and |:checkhealth| conduit shows them per agent.

A prompt starting with `/name` is sent unchanged and the agent runs the
command. From the inline prompt, a command is sent as is with the selected
lines attached as context, and the reply opens in an answer float.

                                                             *conduit-inline*
Inline requests work on a range. Without a request on the command line, a
floating prompt opens under the range (above it near the bottom of the window)
with `@` completion. Its title shows the agent, the mode and the lines:

  <CR>      Submit
  <S-CR>    Add a line (insert)
  <C-t>     Cycle the mode (Auto, Edit, Ask)
  <C-c>     Cancel (insert)
  q <Esc>   Close (normal)
  g?        List the keys (normal)

A leading `?` forces Ask and `!` forces Edit; the title updates as you type.

In Auto mode the agent decides: changes replace the range as one undoable
change, and answers stream into a float under the range. In the float:

  a         Apply the answer's last code block to the range
  f         Ask a follow-up in the same session
  c         Move the conversation into the chat, keeping the session
  <C-c>     Cancel the answer
  q <Esc>   Close
  g?        List the keys

While a request runs or its answer is open, the range is highlighted
(`ConduitInlinePending`) and marked in the sign column (`ConduitInlineSign`),
and a spinner above it shows progress (`ConduitInlineStatus`). Each request
runs in its own session; see `inline.options` in |conduit-setup|.

                                                         *conduit-highlights*
Highlight groups, all defined with `default` links so colorschemes can
override them:

  ConduitNormal         NormalFloat     Float background
  ConduitBorder         FloatBorder     Float border
  ConduitTitle          FloatTitle      Answer title
  ConduitAgent          Title           Agent name
  ConduitContext        Comment         File and lines in the prompt title
  ConduitModeAuto       Special         Mode label: Auto
  ConduitModeEdit       DiagnosticWarn  Mode label: Edit
  ConduitModeAsk        DiagnosticInfo  Mode label: Ask
  ConduitHintKey        Special         Keys in footer hints
  ConduitHintDesc       Comment         Descriptions in footer hints
  ConduitPlaceholder    Comment         Empty prompt placeholder
  ConduitSpinner        DiagnosticInfo  Progress spinner
  ConduitInlinePending  CursorLine      Range while a request runs
  ConduitInlineSign     DiagnosticInfo  Sign column mark on the range
  ConduitInlineStatus   Comment         Progress text

5. LUA API                                                       *conduit-api*

require("conduit").setup({opts})         Configure the plugin.
require("conduit").open({agent?})        Open or create a thread.
require("conduit").new({agent?})         Start a new thread.
require("conduit").toggle()              Toggle the current thread.
require("conduit").threads({agent?})     Pick a live or past thread.
require("conduit").continue_thread({agent?})
                                         Latest thread, reopening past ones.
require("conduit").thread_next()         Switch to the next thread.
require("conduit").thread_prev()         Switch to the previous thread.
require("conduit").thread_close()        Close the current thread.
require("conduit").thread_delete({opts?})
                                         Delete it for good. `{ force = true }`
                                         skips the confirmation.
require("conduit").thread_fork()         Fork the current thread.
require("conduit").thread_rename({title?})
                                         Rename the current thread.
require("conduit").current               The current thread (a chat), or nil.
require("conduit").cancel()              Cancel the current turn.
require("conduit").stop()                Stop all agents.
require("conduit").add_range({l1}, {l2}) Add lines to the prompt.
require("conduit").inline({l1}, {l2}, {r?}, {mode?})
                                         Inline edit or answer about lines.
require("conduit").ask({l1}, {l2}, {q?})  Inline answer about lines.
require("conduit").edit({l1}, {l2}, {i?}) Inline edit of lines.
require("conduit").option({key?}, {value?})
                                         Pick or set a session option.
require("conduit").commands({name?})     Pick a slash command (or use {name})
                                         and start the chat prompt with it.
