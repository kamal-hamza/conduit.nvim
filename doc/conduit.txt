1. INTRODUCTION                                         *conduit-introduction*

conduit.nvim makes Neovim an Agent Client Protocol (ACP) client. It spawns an
ACP agent (Claude Code, Gemini CLI, Codex, ...) as a subprocess and talks
JSON-RPC to it over stdio. Agent file reads and writes go through loaded
buffers when there are any, so agents see unsaved changes.

See https://agentclientprotocol.com for the protocol.

==============================================================================
2. SETUP                                                       *conduit-setup*

>lua
  require("conduit").setup({
    default_agent = "claude",
    agents = {
      claude = { cmd = "npx", args = { "-y", "@agentclientprotocol/claude-agent-acp" } },
      gemini = { cmd = "gemini", args = { "--experimental-acp" } },
      codex = { cmd = "npx", args = { "-y", "@agentclientprotocol/codex-acp" } },
    },
    ui = {
      width = 0.4,
      input_height = 6,
      icons = false,
      spinner = { "⠋", "⠙", "⠹", "⠸", "⠼", "⠴", "⠦", "⠧", "⠇", "⠏" },
      inline = { width = { min = 40, max = 84 } },
      picker = "auto",
      thread_bar = true,
    },
    inline = { agent = nil, options = {}, mcp_servers = false },
    mcp_servers = {},
    mentions = { completion = "auto" },
    threads = {
      scope = "cwd",
      persist = true,
      max_listed = 200,
      hide_inline = true,
      notify = true,
    },
    tools = {
      diff_lines = 20,
      output_lines = 8,
      hide_output = { read = true, search = true, fetch = true },
    },
    terminal = { enabled = true, output_limit = 1048576 },
    review = {
      enabled = true,
      chat = true,
      inline = false,
      keys = {
        next = "]r", prev = "[r",
        accept = "<localleader>a", reject = "<localleader>r",
        accept_file = "<localleader>A", reject_file = "<localleader>R",
      },
    },
    log_level = vim.log.levels.WARN,
  })
<
Each agent takes `cmd`, plus optional `args`, `env`, `options` and
`mcp_servers` (see |conduit-mcp|). Calling
setup() is optional if you're happy with the defaults.

`ui.icons` adds Nerd Font glyphs to float titles. `ui.spinner` is the progress
animation; a single frame turns it off. `ui.inline.width` bounds the inline
prompt and answer floats. Floats use 'winborder' when it has a top edge, else
a rounded border. `ui.picker` picks threads and search results with
"snacks", "telescope", "fzf_lua", "mini_pick" or "select" (|vim.ui.select()|);
"auto" uses the first of those plugins that's loaded. It can also be a
function taking the picker spec (see `lua/conduit/ui/picker.lua`).
`ui.thread_bar` shows threads as tabs in the chat's winbar
(|conduit-threads|). `review` controls review of agent edits
(|conduit-review|).

                                                            *conduit-options*
`options` are session options applied to every new session, keyed by option id
or ACP category, e.g. `{ model = "opus", effort = "high" }`. `effort` is an
alias for the `thought_level` category. `inline.options` are layered over
them for inline edits. Values depend on the agent; see |:Conduit| `option`.

`threads` configures |conduit-threads|: `scope` is "cwd" (past threads started
in the current directory) or "all"; `persist` keeps a local index of thread ids
and titles (never transcripts); `max_listed` caps how many past threads are
fetched; `hide_inline` leaves inline requests' sessions out of thread lists;
`notify` tells you when a thread you aren't looking at finishes a turn or asks
for permission.

`tools` configures tool calls in the chat (|conduit-tool-calls|): `diff_lines`
and `output_lines` cap the preview under each call, and `hide_output` lists
tool kinds whose output stays hidden until the call is expanded.

                                                                *conduit-mcp*
`mcp_servers` lists MCP servers that conduit passes to the agent with every
session (`mcpServers` in ACP). The agent starts them and can use their tools;
conduit never runs them itself. Servers are keyed by name:
>lua
  mcp_servers = {
    github = {
      command = "github-mcp",
      args = {},
      env = { GITHUB_TOKEN = function() return os.getenv("GH_TOKEN") end },
    },
    docs = { type = "http", url = "https://example.com/mcp", headers = {} },
  },
<
`type` is "stdio" (default), "http" or "sse". Stdio servers take `command`
(looked up in PATH and sent as an absolute path), `args` and `env`. HTTP and
SSE servers take `url` and `headers`. Values in `env`, `headers` and `args` can
be functions, called when a session opens. `enabled = false`, or a function
that returns false, turns a server off. A list of servers with `name` fields is
accepted too.

An agent's own `mcp_servers` replace global ones of the same name, and `false`
leaves a global server out for that agent: >lua
  agents = { gemini = { cmd = "gemini", mcp_servers = { docs = false } } }
<
Servers that can't be sent are skipped with a warning: the command isn't
found, `url` is missing, or the agent doesn't advertise the transport in
`mcpCapabilities` (every agent supports stdio). Inline requests open a new
session each time, so they leave servers out unless `inline.mcp_servers` is
true. |:checkhealth| conduit shows what each agent would get.

Claude Code also loads servers from its own config (`~/.claude.json`,
`.mcp.json`); a server listed in both places starts twice.

3. COMMANDS                                                 *conduit-commands*

                                                                    *:Conduit*
:Conduit [toggle]       Toggle the chat window.
:Conduit open [agent]   Open the current thread. Naming a different agent
                        switches to its latest thread, or starts one.
:Conduit new [agent]    Start a new thread (chat and ACP session). Earlier
                        threads stay alive. See |conduit-threads|.
:Conduit threads [agent]
                        Pick a live or past thread, or start a new one.
:Conduit continue [agent]
                        Go back to the latest live thread, or reopen the
                        most recent past thread in this directory.
:Conduit resume [session-id]
                        Reopen a thread by session id (live, in the agent's
                        history, or any session it can load). Without an id,
                        pick one of the agent's past threads.
:Conduit thread {action} [args]
                        `new`, `next`, `prev`; `alt` switches to the thread
                        used before this one; `goto {n|title|id}` goes to a
                        thread by its number in the thread bar, its title
                        (or a unique part of it) or its session id, else
                        opens the picker with that query; `search [--qf]
                        [text]` searches live transcripts (|conduit-threads|);
                        `close` the current thread (it stays in the
                        history); `delete` it for good (asks first); `fork`
                        it; `rename [title]` it.
:[range]Conduit add     Add [range] to the prompt as a fenced code block.
:[range]Conduit inline [request]
                        Edit [range] in place or answer a question about it
                        in a float, as the agent decides. Prompts for the
                        request when omitted. See |conduit-inline|.
:[range]Conduit ask [question]
                        Like `inline`, always answering in a float.
:[range]Conduit edit [instruction]
                        Like `inline`, always rewriting [range].
:Conduit model [value]  Pick or set the session model.
:Conduit effort [value] Pick or set the reasoning effort.
:Conduit mode [value]   Pick or set the session mode.
:Conduit option [id] [value]
                        Pick or set any session option.
:Conduit commands [name]
                        Pick one of the agent's slash commands (or use
                        [name]) and start the chat prompt with it. See
                        |conduit-slash-commands|.
:Conduit review         List the agent's changes waiting for review in the
                        quickfix list. See |conduit-review|.
:Conduit review toggle [chat|inline]
                        Turn review of agent edits on or off, everywhere or
                        for chat turns or inline requests only.
:Conduit accept [all]   Accept the agent's changes to the current file, or
                        to every file with `all`.
:Conduit reject [all]   Reject the agent's changes to the current file, or
                        to every file with `all`.
:Conduit cancel         Cancel running inline edits, or else the chat turn.
:Conduit stop           Terminate all agent processes.
:Conduit log            Open the log file.

4. CHAT BUFFER                                                  *conduit-chat*

The chat is a markdown transcript with a prompt buffer below it.

  <CR>      (prompt, normal)  Send the prompt
  <C-s>     (prompt, insert)  Send the prompt
  <C-c>     (prompt, normal)  Cancel the running turn
  go        (both)            Pick a session option (model, effort, mode)
  gs        (both)            Pick a thread
  gn        (both)            Start a new thread with the same agent
  ]t  [t    (both)            Next / previous thread
  g<Tab>    (both)            The thread used before this one
  q         (both)            Close the chat window

Tool permission requests are shown with |vim.ui.select()|. The prompt shows
the tool's kind (`edit`, `execute`, ...), the paths it touches and, for
commands, every line of the command. The buffers use the `conduit` and
`conduit_input` filetypes with treesitter markdown highlighting, so markdown
linters and LSPs don't attach to them. The prompt's winbar shows the agent, its
state and the current model, effort and mode.

                                                         *conduit-tool-calls*
Each tool call shows its status and title, then the files it touched, the diff
of any edit it made or proposes, and its output. Diffs and output are cut to
`tools.diff_lines` and `tools.output_lines`; output from `read`, `search` and
`fetch` calls stays hidden until expanded. When the agent asks permission for
an edit, the proposed diff is drawn before the prompt opens. In the transcript:

  <CR>      Expand or collapse the tool call under the cursor
  gd        Open its diff side by side in a new tab (`q` closes it)
  gf        Open the first file it touched, at the reported line
  <localleader>A  <localleader>R
            Accept / reject the changes it made (|conduit-review|)

Diffs are highlighted by the treesitter `diff` parser, which Neovim doesn't
bundle; |:checkhealth| conduit reports whether it's installed.

                                                             *conduit-review*
Agents like Claude Code and Codex write files themselves, so edits can't be
held back for approval. Instead conduit keeps each file's content from before
the agent first touched it and shows what changed since as hunks to accept or
reject, whether the agent asked permission first or not.

When an edit lands, the file's buffer reloads (if it's open without unsaved
changes), the agent's lines are highlighted and the lines it removed show as
virtual lines above them. The tool call's status line reads "review pending",
then "accepted", "rejected" or "reviewed" (some of each), and the chat notes
how many files are waiting at the end of a turn. In a file with changes:

  ]r  [r            Next / previous change
  <localleader>a    Accept the change under the cursor
  <localleader>r    Reject it: the old lines come back and the file is saved
  <localleader>A    Accept every change in the file
  <localleader>R    Reject every change in the file

The keys are `review.keys` (`false` disables one). Rejecting a file the agent
created deletes it; rejecting one it deleted recreates it. Editing a reviewed
buffer updates the hunks, and undoing a change by hand clears it. If the agent
rewrites a file whose buffer has unsaved changes, the buffer is left alone and
the file is listed as a conflict; rejecting it writes back what the buffer had
when the agent started.

`review.chat` (on) and `review.inline` (off) choose which edits are reviewed;
`review.enabled = false` turns review off and edits apply as they come. Pair
that with the agent's `mode = "acceptEdits"` option for no prompts at all.
`:Conduit review toggle` flips them for the session. A `User`
`ConduitReviewChanged` autocmd fires, with `{ path }` in `data`, when a file's
review state changes.

Edits are tracked through tool calls that report their files (`edit`,
`delete` and `move` kinds, or any call with a diff), `fs/write_text_file` and
inline replies. Files changed by shell commands aren't tracked.

                                                          *conduit-terminals*
Agents can ask Neovim to run commands for them (ACP terminals). Each command
runs as a process in the session's directory with the environment the agent
asks for; the agent gets its combined stdout and stderr (at most
`terminal.output_limit` bytes, oldest dropped first), and its exit code or
signal. Commands are killed when the agent releases them, when their thread
closes, when the agent exits, and when Neovim quits. A command sent as a whole
shell line with no arguments runs through `sh -c`.

A tool call that runs a command shows the last `tools.output_lines` lines of
output, updated live, followed by the exit code or signal if it failed. <CR>
expands it to the whole output. Agents that run commands themselves (Claude
Code, Codex) report output the same way, through tool call `_meta`.

`terminal.enabled = false` stops offering terminals to agents. Output from
agents that run commands themselves is still shown.

                                                            *conduit-threads*
Each chat is a thread: one ACP session with its own transcript. Starting a new
thread keeps the others alive, and switching shows the chosen thread in the
same chat windows. Titles come from the agent's `session_info_update`, from
`:Conduit thread rename` (these stick), or from the first line of your first
prompt. Inline answers moved into the chat (|conduit-inline|) become threads.

Beyond live threads, features follow the agent's capabilities:

  none                 Live threads until Neovim exits.
  loadSession          Reopen past threads, replaying their transcript. Past
                       threads come from conduit's local index.
  session list         Past threads come from the agent (`session/list`),
                       including ones started outside Neovim.
  session resume       Reconnect after the agent restarts without a replay.
  session close        Closing a thread frees the agent's session.
  session delete       Deleting removes it from the agent's history. Without
                       it, deleted threads are hidden from conduit's lists.
  session fork         `:Conduit thread fork`.
  session title        Renames are stored by the agent (`session/set_title`).

                                                         *conduit-thread-bar*
The chat's winbar lists every live thread as a numbered tab (the numbers work
with `:Conduit thread goto`), marking threads that are working (`◐`), waiting
for a permission answer (`!`) or finished a turn you haven't seen (`●`). In
narrow windows titles shrink, and `‹` `›` mark tabs that don't fit. With
`ui.thread_bar = false` the winbar shows the title, the thread's position
(e.g. `(2/3)`) and its state instead.

                                                      *conduit-thread-picker*
The picker (`gs`, |:Conduit| `threads`) lists live threads (most recently used
first, the current one last), then past threads from the current agent and any
other running agent, then "New thread". With snacks.nvim, telescope.nvim,
fzf-lua or mini.pick (`ui.picker`) it previews each thread's transcript, and
(except fzf-lua) opens at once and adds past threads as they arrive. Keys:

  <CR>      Open the thread
  <C-d>     Delete the thread (asks first)
  <C-r>     Rename it (past threads are renamed locally)
  <C-f>     Fork it
  <C-n>     Start a new thread
  <C-g>     Toggle this directory's past threads / all of them

With |vim.ui.select()| the same threads are listed and the chosen one opens.

`:Conduit thread search` looks through live transcripts (past transcripts stay
with the agent): plain text, ignoring case unless the text has capitals.
Matches open in the picker, which jumps to the line, or with `--qf` in the
quickfix list.

                                                           *conduit-events*
conduit fires |User| autocmds as threads change, with
`{ agent, session_id, title }` in `data`: `ConduitThreadCreated`,
`ConduitThreadSwitched`, `ConduitThreadUpdated` (title or state) and
`ConduitThreadClosed`.

When the agent process exits, the transcript
stays; the next prompt restores the session by resuming it, else reloading it
silently, else starting a new session with a notice. |:checkhealth| conduit
shows what each running agent supports. The local index is
`stdpath("data")/conduit/threads.json`.

                                                           *conduit-mentions*
Type `@` in the chat prompt or the inline prompt to attach context:

  @path/file      The file's contents (from its buffer if open)
  @dir/           A listing of the directory
  @shot.png       The image, if the agent accepts images
  @buffer         The buffer you were last in
  @selection      Your last visual selection in that buffer
  @diagnostics    Diagnostics from all open buffers
  @quickfix       The quickfix list
  @diff           Uncommitted changes (`git diff HEAD`)

Mentions that don't match anything are left as plain text. Agents without
embedded-context support get resource links for files.

PNG, JPEG, GIF and WebP images (recognised by their contents) are sent as ACP
`image` blocks when the agent advertises `promptCapabilities.image`. Images
over 5 MB, or mentioned to an agent without image support, are sent as links
with a warning. |:checkhealth| conduit shows which running agents accept
images.

Completion uses blink.cmp when it is loaded (a `conduit` source is registered
for the `conduit_input` filetype automatically), otherwise the native popup.
Set `mentions = { completion = "blink" | "native" }` to force one.

                                                     *conduit-slash-commands*
Agents advertise their own commands (`available_commands_update`), such as
`/review`, `/compact` and `/init` for Claude Code. Type `/` at the very start
of the chat prompt or the inline prompt to complete them, with descriptions in
the completion docs. Commands that take arguments show their input hint as
ghost text after `/name ` until you type some. `:Conduit commands` lists them
with |vim.ui.select()|, and |:checkhealth| conduit shows them per agent.

A prompt starting with `/name` is sent unchanged and the agent runs the
command. From the inline prompt, a command is sent as is with the selected
lines attached as context, and the reply opens in an answer float.

                                                             *conduit-inline*
Inline requests work on a range. Without a request on the command line, a
floating prompt opens under the range (above it near the bottom of the window)
with `@` completion. Its title shows the agent, the mode and the lines:

  <CR>      Submit
  <S-CR>    Add a line (insert)
  <C-t>     Cycle the mode (Auto, Edit, Ask)
  <C-c>     Cancel (insert)
  q <Esc>   Close (normal)
  g?        List the keys (normal)

A leading `?` forces Ask and `!` forces Edit; the title updates as you type.

In Auto mode the agent decides: changes replace the range as one undoable
change, and answers stream into a float under the range. In the float:

  a         Apply the answer's last code block to the range
  f         Ask a follow-up in the same session
  c         Move the conversation into the chat, keeping the session
  <C-c>     Cancel the answer
  q <Esc>   Close
  g?        List the keys

While a request runs or its answer is open, the range is highlighted
(`ConduitInlinePending`) and marked in the sign column (`ConduitInlineSign`),
and a spinner above it shows progress (`ConduitInlineStatus`). Each request
runs in its own session; see `inline.options` in |conduit-setup|.

                                                         *conduit-highlights*
Highlight groups, all defined with `default` links so colorschemes can
override them:

  ConduitNormal         NormalFloat     Float background
  ConduitBorder         FloatBorder     Float border
  ConduitTitle          FloatTitle      Answer title
  ConduitAgent          Title           Agent name
  ConduitContext        Comment         File and lines in the prompt title
  ConduitModeAuto       Special         Mode label: Auto
  ConduitModeEdit       DiagnosticWarn  Mode label: Edit
  ConduitModeAsk        DiagnosticInfo  Mode label: Ask
  ConduitHintKey        Special         Keys in footer hints
  ConduitHintDesc       Comment         Descriptions in footer hints
  ConduitPlaceholder    Comment         Empty prompt placeholder
  ConduitSpinner        DiagnosticInfo  Progress spinner
  ConduitInlinePending  CursorLine      Range while a request runs
  ConduitInlineSign     DiagnosticInfo  Sign column mark on the range
  ConduitInlineStatus   Comment         Progress text
  ConduitThreadActive   Title           Current thread's tab and marker
  ConduitThreadInactive Comment         Other threads' tabs
  ConduitThreadSeparator WinSeparator   Between tabs
  ConduitThreadBusy     DiagnosticInfo  Working / loading
  ConduitThreadUnread   DiagnosticWarn  Finished while you weren't looking
  ConduitThreadWaiting  DiagnosticError Waiting for a permission answer
  ConduitThreadNew      Special         "New thread" in the picker
  ConduitThreadMeta     Comment         Agent, age and directory in the picker
  ConduitSearchMatch    Search          Matched text in search results
  ConduitReviewAdd      DiffAdd         Lines the agent added
  ConduitReviewChange   DiffChange      Lines the agent changed
  ConduitReviewDelete   DiffDelete      Lines the agent removed (virtual)
  ConduitReviewSign     DiagnosticInfo  Sign column mark on changes
  ConduitReviewHint     Comment         Accept / reject key hint

5. LUA API                                                       *conduit-api*

require("conduit").setup({opts})         Configure the plugin.
require("conduit").open({agent?})        Open or create a thread.
require("conduit").new({agent?})         Start a new thread.
require("conduit").toggle()              Toggle the current thread.
require("conduit").threads({agent?})     Pick a live or past thread.
require("conduit").continue_thread({agent?})
                                         Latest thread, reopening past ones.
require("conduit").thread_next()         Switch to the next thread.
require("conduit").thread_prev()         Switch to the previous thread.
require("conduit").thread_alternate()    Switch to the thread used before.
require("conduit").thread_goto({target?})
                                         Go to a thread by number, title or id.
require("conduit").thread_search({text?}, {opts?})
                                         Search live transcripts. `{ qf = true }`
                                         fills the quickfix list.
require("conduit").resume({id?}, {agent?})
                                         Reopen a thread by session id.
require("conduit").status()              `{ current, count, busy, unread,
                                         waiting }` for statuslines.
require("conduit").thread_close()        Close the current thread.
require("conduit").thread_delete({opts?})
                                         Delete it for good. `{ force = true }`
                                         skips the confirmation.
require("conduit").thread_fork()         Fork the current thread.
require("conduit").thread_rename({title?})
                                         Rename the current thread.
require("conduit").current               The current thread (a chat), or nil.
require("conduit").cancel()              Cancel the current turn.
require("conduit").stop()                Stop all agents.
require("conduit").add_range({l1}, {l2}) Add lines to the prompt.
require("conduit").inline({l1}, {l2}, {r?}, {mode?})
                                         Inline edit or answer about lines.
require("conduit").ask({l1}, {l2}, {q?})  Inline answer about lines.
require("conduit").edit({l1}, {l2}, {i?}) Inline edit of lines.
require("conduit").option({key?}, {value?})
                                         Pick or set a session option.
require("conduit").commands({name?})     Pick a slash command (or use {name})
                                         and start the chat prompt with it.
require("conduit").review({action?}, {source?})
                                         List changes to review in the
                                         quickfix list; `"toggle"` turns review
                                         on or off (for "chat" or "inline").
require("conduit").accept({all?})        Accept the agent's changes to the
                                         current file, or all of them.
require("conduit").reject({all?})        Reject them.
