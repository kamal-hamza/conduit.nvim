1. INTRODUCTION                                         *conduit-introduction*

conduit.nvim is a minimal way to use AI coding agents in Neovim. It keeps
Neovim a text editor: there is no chat panel. Select some lines and say what
you want. Changes land in the file as hunks to review; explanations open in a
read-only sidebar that never takes focus. Everything the agent does is kept in
a per-project history, and a sandbox decides what it may touch and run.

Neovim acts as an Agent Client Protocol (ACP) client: conduit spawns an ACP
agent (Claude Code, Gemini CLI, Codex, ...) as a subprocess and talks JSON-RPC
to it over stdio. Agent file reads and writes go through loaded buffers when
there are any, so agents see unsaved changes.

See https://agentclientprotocol.com for the protocol.

2. SETUP                                                       *conduit-setup*

>lua
  require("conduit").setup({
    default_agent = "claude",
    agents = {
      claude = { cmd = "npx", args = { "-y", "@agentclientprotocol/claude-agent-acp" } },
      gemini = { cmd = "gemini", args = { "--experimental-acp" } },
      codex = { cmd = "npx", args = { "-y", "@agentclientprotocol/codex-acp" } },
    },
    ui = {
      icons = true,             -- true, false (ASCII) or "nerd"
      spinner = { "⠋", "⠙", "⠹", "⠸", "⠼", "⠴", "⠦", "⠧", "⠇", "⠏" },
      inline = { width = { min = 40, max = 84 } },
      sidebar = { width = 0.35, position = "right" },
      border = nil,
      components = {},
    },
    inline = { agent = nil, options = {}, mcp_servers = false },
    history = { enabled = true, max_entries = 1000 },
    mcp_servers = {},
    mentions = { completion = "auto" },
    terminal = { enabled = true, output_limit = 1024 * 1024 },
    review = {
      enabled = true,
      replies = true,
      keys = {
        next = "]r", prev = "[r",
        accept = "<localleader>a", reject = "<localleader>r",
        accept_file = "<localleader>A", reject_file = "<localleader>R",
      },
    },
    sandbox = {
      enabled = true,
      roots = {},
      outside = "deny",
      commands = { default = "ask", allow = { ... }, deny = { ... } },
      isolation = {
        enabled = true, network = false, writable = {},
        env = "inherit", unavailable = "ask",
      },
      bypass = false,
    },
    log_level = vim.log.levels.WARN,
  })
<
                                                            *conduit-options*
Agents ~
  `agents.{name}`         `{ cmd, args?, env?, options?, mcp_servers?,
                        session_meta? }`. `options` are session options
                        applied to every session, keyed by id or category,
                        e.g. `{ model = "opus", effort = "high" }`.
                        `session_meta` is extra `_meta` for `session/new`.
Inline ~
  `inline.agent`          Agent for requests (default: `default_agent`).
  `inline.options`        Session options for every request. `:Conduit model`
                        and friends change it for the rest of the session.
  `inline.mcp_servers`    Give requests the MCP servers (|conduit-mcp|).
UI ~
  `ui.sidebar`            `width` (fraction of the editor, or columns) and
                        `position` ("right" or "left") of the answer sidebar.
  `ui.inline.width`       Width of the inline prompt.
  `ui.border`             Border for floats; nil follows 'winborder'.
History ~
  `history.enabled`       Keep the history (|conduit-history|).
  `history.max_entries`   Most entries kept per project.
Review and sandbox ~
  See |conduit-review| and |conduit-sandbox|.

                                                                *conduit-mcp*
`mcp_servers` lists MCP servers that conduit hands to the agent when a session
opens (ACP `mcpServers`). The agent runs them; conduit doesn't.
>lua
  mcp_servers = {
    github = { command = "github-mcp", env = { TOKEN = function() return os.getenv("GH") end } },
    docs = { type = "http", url = "https://example.com/mcp", headers = {} },
  }
<
`type` is "stdio" (default), "http" or "sse". Values in `env`, `headers` and
`args` may be functions, called when a session opens. `enabled = false` turns a
server off. Per-agent `mcp_servers` replace global ones of the same name;
`false` leaves one out. Every request is a new session, so servers are left out
unless `inline.mcp_servers = true`. Servers that can't be sent (command not in
PATH, transport not supported) are skipped with a warning.

3. COMMANDS                                                 *conduit-commands*

:[range]Conduit                    Open the prompt for the lines.
:[range]Conduit inline [request]   Edit the lines or answer about them.
:[range]Conduit ask [question]     Answer about the lines, in the sidebar.
:[range]Conduit edit [instruction] Rewrite the lines in place.
:Conduit answer                    Focus the sidebar (latest answer).
:Conduit sidebar                   Open or close the sidebar.
:Conduit history [qf|all]          Browse the history (|conduit-history|).
:Conduit review [toggle]           List changes to review in the quickfix
                                   list, or turn review on or off.
:Conduit accept [all]              Accept the agent's changes to this file.
:Conduit reject [all]              Reject them.
:Conduit model [value]             Pick or set the model for new requests.
:Conduit effort [value]            Pick or set the reasoning effort.
:Conduit mode [value]              Pick or set the mode.
:Conduit option [id] [value]       Pick or set any session option.
:Conduit sandbox                   Show what the sandbox allows.
:Conduit cancel                    Cancel running requests.
:Conduit stop                      Kill all agent processes.
:Conduit log                       Open the log file.

<Plug> mappings: `<Plug>(conduit-inline)`, `-ask`, `-edit` (normal and visual
mode), `-answer`, `-sidebar`, `-history`, `-cancel`, `-model`, `-options`.

4. INLINE REQUESTS                                            *conduit-inline*

Select lines and run `:'<,'>Conduit` (or a <Plug> mapping). A floating prompt
opens under the selection with `@` completion. Its title shows the agent, the
mode, the model and effort, and the lines.

  Auto    The agent decides: a change rewrites the lines in place as one
          undoable change; a question opens the answer in the sidebar.
  Edit    Always rewrite. Start the prompt with `!`.
  Ask     Always answer. Start the prompt with `?`.

In the prompt: <CR> sends, <S-CR> adds a line, <C-t> cycles the mode, <C-o>
changes options for this request only, <C-c> (insert) or `q` / <Esc> (normal)
closes it, `g?` lists the keys. While the agent works, a spinner and its name
sit above the lines. Changes the request needs in other files are made by the
agent's own tools and reviewed in those files (|conduit-review|).

                                                            *conduit-sidebar*
Answers stream into a read-only split (`ui.sidebar`, filetype `conduit`,
parsed as markdown). It never takes focus on its own; `:Conduit answer` gets
you in. Its winbar shows what the agent is doing. A new answer replaces the
previous one, which stays in the history. Keys:

  f         Follow up in the same session. On a history entry, a new
            request with the old conversation as context.
  a         Replace the request's lines with the answer's last code block
  gf        Go to the request's lines
  [[  ]]    Older / newer answer from the history
  gh        Browse the history
  <C-c>     Cancel the reply
  q         Close the sidebar
  g?        List the keys

                                                            *conduit-history*
Everything the agent does is kept per project, as JSONL under
`stdpath("state")/conduit/history`:

  answer    The request, the conversation (with follow-ups) and the tools the
            agent ran, with how each permission request was answered.
  edit      The lines before and after, and the outcome: applied, pending
            review, accepted, rejected or reverted.
  change    A file the agent changed with its own tools, as a diff, with what
            was kept after review.

Commands run through Neovim are recorded with the request that ran them: the
sandbox decision, whether they were isolated, and how they exited.

`:Conduit history` lists this buffer's entries (<Tab> switches to the whole
project): `j`/`k` move, `/` filters (prompt, file, answer, diff or kind),
<CR> shows the entry in the sidebar, `gf` goes to its lines, `f` follows up on
an answer, `r` re-runs the request, `u` reverts an edit or change if the file
hasn't changed since, `dd` deletes the entry. `:Conduit history qf` sends the
entries to the quickfix list.

                                                             *conduit-review*
Agents like Claude Code and Codex write files themselves, so edits can't be
held back for approval. Instead conduit keeps each file's content from before
the agent first touched it and shows what changed as hunks to accept or
reject. Inline rewrites of the selection are reviewed the same way
(`review.replies`).

When an edit lands, the file's buffer reloads (if it has no unsaved changes),
the agent's lines are highlighted and the lines it removed show as virtual
lines above them. In a file with changes:

  ]r  [r            Next / previous change
  <localleader>a    Accept the change under the cursor
  <localleader>r    Reject it: the old lines come back and the file is saved
  <localleader>A    Accept every change in the file
  <localleader>R    Reject every change in the file

The keys are `review.keys` (`false` disables one). Rejecting a file the agent
created deletes it; rejecting one it deleted recreates it. Editing a reviewed
buffer updates the hunks, and undoing a change by hand clears it. If the agent
rewrites a file whose buffer has unsaved changes, the buffer is left alone and
the file is listed as a conflict; rejecting it writes back what the buffer had
when the agent started. `review.enabled = false` applies edits as they come.
A `User ConduitReviewChanged` autocmd fires, with `{ path }` in `data`, when a
file's review state changes.

Edits are tracked through tool calls that report their files (`edit`,
`delete` and `move` kinds, or any call with a diff), `fs/write_text_file` and
inline replies. Files changed by shell commands aren't tracked.

                                                            *conduit-sandbox*
What the agent may do, in three layers (`sandbox`):

Paths ~
`fs/*` requests, edits and shell redirections must stay inside the roots: the
working directory plus `sandbox.roots`. Outside them they are refused
(`outside = "deny"`) or asked about (`"ask"`).

Commands ~
A command line is split at `&&`, `||`, `;`, `|`, `&` and newlines, wrappers
(`env`, `command`, `exec`, `nohup`, `time`, `nice`, `xargs`, `timeout`) and
leading `VAR=value` assignments are looked through, and each part is matched
against `sandbox.commands` (Lua patterns): refused if any part matches `deny`,
run without asking if every part matches `allow`, otherwise `default` ("ask",
"allow" or "deny"). Command substitution always asks. Setting `allow` or
`deny` replaces the default list.

The policy answers ACP `terminal/create` requests and the permission requests
of agents that run commands themselves (Claude Code, Codex): a denied command
is refused without a prompt, an allowed one runs without one, and when it asks
the prompt says why.

Isolation ~
Commands Neovim runs for the agent (ACP terminals) run under `sandbox-exec`
(macOS) or `bwrap` (Linux): writes only to the roots, `isolation.writable` and
temp dirs, and no network unless `isolation.network = true`.
`isolation.env = "minimal"` passes only PATH, HOME, USER, SHELL, TERM, locale
and TMPDIR. With no OS sandbox installed, `isolation.unavailable` decides:
"ask" (default), "run" or "deny".

Claude Code ~
Claude Code runs Bash itself, and its own permission settings may let it run
commands without asking. Every session's `_meta.claudeCode.options` carries
settings for Claude's adapter: a Bash `ask` rule (which beats allow rules in
your Claude settings), so every command comes back as a permission request for
the policy; Claude Code's own sandbox (`sandbox.enabled`) when
`isolation.enabled` is on; and the roots as additional directories. Other
agents ignore it. An agent's `session_meta` is merged over it.

Agents' bypass-permissions modes skip every check, so conduit won't switch to
one, and removes it from Claude's sessions, unless `sandbox.bypass = true`.

The patterns are a guardrail, not a boundary; OS isolation is the boundary.
`:Conduit sandbox` and |:checkhealth| conduit show what is in effect.

                                                          *conduit-terminals*
Agents can ask Neovim to run commands for them (ACP terminals), under
|conduit-sandbox|. Each command runs in the session's directory with the
environment the agent asks for; the agent gets its combined stdout and stderr
(at most `terminal.output_limit` bytes, oldest dropped first) and its exit
code or signal. Commands are killed when the agent releases them, when their
session closes, when the agent exits, and when Neovim quits. A command sent as
a whole shell line with no arguments runs through `sh -c`.
`terminal.enabled = false` stops offering terminals.

                                                           *conduit-mentions*
Type `@` in the prompt to attach context:

  @path/file      The file's contents (from its buffer if open)
  @dir/           A listing of the directory
  @shot.png       The image, if the agent accepts images
  @buffer         The buffer you were last in
  @selection      Your last visual selection in that buffer
  @diagnostics    Diagnostics from all open buffers
  @quickfix       The quickfix list
  @diff           Uncommitted changes (`git diff HEAD`)

Mentions that don't match anything are left as plain text. Agents without
embedded-context support get resource links for files. Images over 5 MB, or
mentioned to an agent without image support, are sent as links with a warning.
Completion uses blink.cmp when it is loaded (a `conduit` source is registered
for the `conduit_input` filetype automatically), otherwise the native popup.

                                                     *conduit-slash-commands*
Agents advertise their own commands (`/review`, `/compact`, ...). Type `/` at
the start of the prompt to complete them; commands that take arguments show
their input hint as ghost text. A command is sent as is, with the selected
lines attached, and the reply opens in the sidebar.

                                                         *conduit-components*
The drawn pieces are components: pure functions from props to spans
(`{ text, highlight_group }`). Replace or wrap one in `ui.components`; each
gets its props and the built-in. An override that errors falls back to the
built-in.

  HelpFloat     title, entries, query?         (returns lines)
  Picker        model                          (returns lines)
  PromptTitle   agent?, mode?, mode_hl?, model?, effort?, range
  HistoryLine   entry, now, cursor?

                                                         *conduit-highlights*

  ConduitNormal         NormalFloat     Float background
  ConduitBorder         FloatBorder     Float border
  ConduitTitle          FloatTitle      Float titles
  ConduitAgent          Title           Agent name
  ConduitContext        Comment         File and lines in the prompt title
  ConduitModeAuto       Special         Mode label: Auto
  ConduitModeEdit       DiagnosticWarn  Mode label: Edit
  ConduitModeAsk        DiagnosticInfo  Mode label: Ask
  ConduitHintKey        Special         Keys in hints
  ConduitHintDesc       Comment         Descriptions in hints
  ConduitPlaceholder    Comment         Empty prompt placeholder, input hints
  ConduitSpinner        DiagnosticInfo  Progress spinner
  ConduitInlinePending  CursorLine      Lines while a request runs
  ConduitInlineSign     DiagnosticInfo  Sign column mark on those lines
  ConduitInlineStatus   Comment         Agent name above them
  ConduitInlineAdded    DiffAdd         Lines an inline edit just wrote
  ConduitMuted          Comment         Quiet text
  ConduitTitleText      Title           Titles
  ConduitPickerCursor   CursorLine      Picker row under the cursor
  ConduitPickerCurrent  Special         Current value in a picker
  ConduitPickerIndex    Comment         Row numbers in a picker
  ConduitHistoryAnswer  DiagnosticInfo  Answers in the history list

  ConduitReviewDelete   DiffDelete      Lines the agent removed (virtual)
  ConduitReviewSign     DiagnosticInfo  Sign column mark on changes

5. LUA API                                                       *conduit-api*

require("conduit").setup({opts})         Configure the plugin.
require("conduit").inline({l1}, {l2}, {r?}, {mode?})
                                         Inline request about lines; returns
                                         the job when {r} is given.
require("conduit").ask({l1}, {l2}, {q?})  Answer about lines.
require("conduit").edit({l1}, {l2}, {i?}) Rewrite lines.
require("conduit").answer()              Focus the sidebar.
require("conduit").sidebar()             Open or close the sidebar.
require("conduit").history({opts?})      Browse the history.
                                         `{ scope = "project" }` lists all of
                                         it, `{ qf = true }` fills quickfix.
require("conduit").review({action?})     List changes to review in the
                                         quickfix list; `"toggle"` turns
                                         review on or off.
require("conduit").accept({all?})        Accept the agent's changes to the
                                         current file, or all of them.
require("conduit").reject({all?})        Reject them.
require("conduit").option({key?}, {value?})
                                         Pick or set a session option for
                                         new requests.
require("conduit").sandbox_info()        What the sandbox allows, as lines.
require("conduit").cancel()              Cancel running requests.
require("conduit").stop()                Stop all agents.
require("conduit").agent({name?})        The agent object (started lazily).
